## 2. 时间线证据链（收益从哪里来）

**(a) 排队量不变——机制不减少排队，只重排谁在等。**
两侧在飞请求数超 cap(16) 的累计时长几乎相同：FCFS 39.8 s vs
core 40.1 s（峰值在飞 32/36）。
资源页也一致：两侧可关联堆同为重 forward 堆，L2/tensor 墙不因策略移动——**收益不来自硬件
利用率**，GPU 侧两条时间线几乎同构（重 forward 堆 21.9 vs 23.8 s，
实例 401,600 vs 396,475）。

**(b) 收益的全部来源：短程序等待被压缩（首 token 前等待 = 排队+prefill）。**

| 类别 | n | FCFS mean/p90 (ms) | core mean/p90 (ms) | Δmean |
|---|---:|---:|---:|---:|
| bfcl | 100 | 48 / 134 | 31 / 48 | +35 % |
| sharegpt | 23 | 130 / 335 | 39 / 73 | +70 % |
| lats | 2317 | 112 / 280 | 117 / 336 | -5 % |

MLFQ 让短程序（bfcl/sharegpt）跳过长程序（lats）的队头阻塞；lats 持平或小幅付出——
与论文 PLAS 语义的预测逐类别一致。

**(c) 机制在 trace 内的自证（MLFQ 账本，core 侧调用记录）：**
离散入队 Q0–Q3 = 151/226/621/1442，量子用尽降级 298 次，
多量子调用 264 个，β 提升 0 次（本负载未触发饥饿线）。
分堆页上的对应签名：core 的重 forward 堆多出 continuation 质量
（+2.0 s、+242 成员），折叠空洞 16,948→16,427。

## 3. 解释链条（一句话）

收益 = **短程序等待压缩 × 排队压力占比**。本模型排队压力（above-cap 时长）为
40 s，故 p90 加速 1.11×。跨模型对照证实该定律：
LLaMA-3.1-8B 169 s→1.86×、Qwen3-1.7B 40 s→1.11×、Qwen2.5-VL-3B 77 s→1.15×——排队压力越大，程序级调度杠杆越大；GPU 侧时间线（堆拓扑、资源墙）三模型
两策略下均不变。
